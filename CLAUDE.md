# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

SheetCards is an **Anki add-on** (not a standalone app) that syncs flashcard decks from Google Sheets into Anki. The repository root *is* the add-on directory: Anki loads `__init__.py` from the root, which registers a `Tools → SheetCards` menu and wires keyboard shortcuts to functions in `src/`. There is no server and no main(); all code runs inside Anki's Python/Qt6 process.

## Commands

Tooling is managed with **uv** (`uv.lock`, Python 3.13 pinned in `.python-version`).

```bash
# Install dev/test deps
uv sync --extra dev          # or: pip install -e ".[dev]"

# Run tests (Anki is auto-mocked by tests/conftest.py — no Anki install needed).
# Use the canonical runner; it sets the required flags (see Note below).
python tests/run_tests.py                  # all tests
python tests/run_tests.py --unit           # only @pytest.mark.unit
python tests/run_tests.py --fast           # skip @pytest.mark.slow
python tests/run_tests.py --coverage       # coverage report → htmlcov/
python tests/run_tests.py --file core_logic --function test_duplicate_ids_detected

# Equivalent direct pytest (the two flags are REQUIRED — see Note):
python -m pytest --rootdir=tests --import-mode=importlib tests/
python -m pytest --rootdir=tests --import-mode=importlib tests/test_core_logic.py::TestUrls

# Lint / format / type-check
ruff check src/ tests/
black src/ tests/            # line-length 88
mypy src/

# Build distributable .ankiaddon packages (interactive menu)
python scripts/build_packages.py
```

**Note (test config):** pytest config lives only in `pyproject.toml` `[tool.pytest.ini_options]` (the old `pytest.ini` was removed). Tests **must** run with `--rootdir=tests --import-mode=importlib`, otherwise pytest builds a `Package` node for the repo-root `__init__.py` (the Anki entry point, which does `from .src...`) and fails to import it. `tests/run_tests.py` passes both flags automatically. `tests/conftest.py` installs an import hook that fabricates *subclassable* `aqt`/`anki` mocks and registers `src` as a package, so the real `src` modules import without Anki. Coverage is opt-in via `--coverage`.

## Architecture

### Layers
- **`__init__.py`** (root) — Anki integration entry point. Builds the menu and binds three user-facing shortcuts (Ctrl+Shift+S sync, C card layout, O settings), plus Ctrl+Shift+T for the dev-only "Import Test Deck". Add and Disconnect have **no shortcut on purpose**: Ctrl+Shift+A is Anki's own Tools → Add-ons and Ctrl+Shift+D the reviewer's Set Due Date, and two actions on one key is an ambiguous shortcut in Qt — neither fires. Check `_aqt/forms/main_qt6.py` and `aqt/reviewer.py` before binding a new one.
- **`src/`** — all add-on logic. The five Qt dialogs live under **`src/ui/`** (plus `url_helpers.py`); foundational shared modules (`compat`, `styled_messages`, `config_manager`, `templates_and_definitions`, …) and the sync/data engine stay at the `src/` root. Modules in `src/ui/` import siblings one level up (`from ..compat import ...`).
- **Facade-split modules**: several large modules were decomposed but keep a back-compat **facade** (re-export) so `from .<module> import X` still resolves: `utils.py` → `errors.py` / `debug.py` (`DebugManager`, `add_debug_message`) / `deck_options.py` / `tsv_model.py`; `data_processor.py` → `tsv_model.py` / `errors.py`; `sync.py` → `sync_report.py` (summary HTML). When grepping for a definition, the real code may live in the split-out module even though imports point at the original.
- **The pure layer** — `errors.py`, `column_model.py`, `sheet_config.py`, `card_layout.py`, `tsv_model.py`, `apkg.py` import nothing but the stdlib and each other. `tsv_model.py` holds everything that turns a sheet into notes: `parse_tsv_data`, `row_to_dict`, `RemoteDeck` and its metrics, `build_remote_deck_from_tsv`, `build_tags`/`clean_tag_text`, `has_cloze_deletion`/`row_has_cloze`, `classify_row` (`GHOST`/`INVALID`/`SKIPPED`/`SYNCED`), `get_subdeck_name`, `get_note_type_name`. **Do not add an Anki, Qt or `compat` import to any of the five** — the preview site (below) runs these exact files in a browser. The add-on hands the pure layer its debug log through `tsv_model.set_addon_logger()`, called once from `data_processor`; `tests/test_pure_modules.py` re-imports the set in a fresh interpreter with `aqt`/`anki` absent, and `scripts/build_site.py` refuses to publish a module that reaches outside it.
- **No runtime third-party dependencies.** The add-on imports nothing but the stdlib and what Anki already provides. The old vendored `libs/` tree (`beautifulsoup4`, `soupsieve`, `chardet`, `org_to_anki`) and its `sys.path` bootstrap in `__init__.py` are **gone** — do not reintroduce a vendoring step or add a runtime dependency. Dev/test tooling is a separate matter (`[project.optional-dependencies] dev`).

### The Qt dialogs draw from Anki, not from a design of their own

`src/theme.py` is an **adapter over `aqt.colors`**, not a palette: every name resolves to the table Anki styles itself from, through the light/dark value Anki would pick. It used to hold ~75 hand-picked hex values on an accent (`#4A90D9`) that was nobody's but ours, spent on gradient banners, white cards over Anki's grey canvas and a border radius Anki does not use — which is how the windows came to look like a Bootstrap page embedded in Anki. Key names are kept because the not-yet-rewritten dialogs still ask for them; where the old palette drew a distinction Anki does not make, the entries collapse onto the one colour there is. `tests/test_theme.py` pins the **rule** (no hex outside the `_FALLBACK` mirror; every value something Qt accepts; a real-Anki subprocess catching the mirror drifting), never the values.

**A rewritten dialog sets no stylesheet at all.** Anki styles `QPushButton`, `QLineEdit`, `QGroupBox`, `QComboBox`, `QTextBrowser` and the rest through a global stylesheet, so staying out of the way *is* the technique; the only rules left in `sync_dialog`, `add_deck_dialog` and `card_layout_dialog` are `color:` on a few secondary labels. Buttons go in a `QDialogButtonBox` — the one thing that puts OK and Cancel in each platform's order. **Nothing is left un-rewritten**: `make_header`, `make_radio_option_card`, `base_dialog_qss`, `groupbox_qss`, `scrollbar_qss`, `primary_button_qss`, `secondary_button_qss` and the `RADIUS_*` scale are all gone with the windows that wanted them — 221 lines out of `theme.py`, which is now a palette adapter, a spacing scale and `icon()`. `styled_messages.py` and the sync summary and progress windows in `sync.py` went the same way: three horizontal bands and a filled button became a layout, and the two private fifteen-colour palettes in `sync.py` (picked by measuring the window's own background lightness, which misreads a custom theme) became `get_colors()`.

**Icons are SVGs in `src/icons/`, inked at load time.** Anki uses no emoji (a grep of `aqt/` finds one llama) and recolours its own SVGs per theme, so `theme.icon(name, color)` reads the file, substitutes the literal `INK` for one of `get_colors()`'s values and renders it — which is what keeps a warning triangle the same red as the sentence beside it on either theme. Emoji were asked for and refused for this reason: they belong to the font, not the theme, and are colour on macOS/Windows, monochrome or missing on a Linux box without Noto Color Emoji, never the colour of the text beside them. An icon failure yields an empty `QIcon` rather than an exception — decoration must not stop a window opening — so **a typo in a name is silent**, and `tests/test_icons.py` is what catches it (plus: every file carries `INK` and no hex of its own, parses as XML with the placeholder still in, shares one `0 0 24 24` box, and is actually used). They ship because the packaging scripts copy `src/` whole.

**Layout can be looked at rather than guessed at.** An offscreen Qt harness boots Anki's real theme against a stubbed `mw.pm` (`QT_QPA_PLATFORM=offscreen`, `WidgetStyle.ANKI`, `theme_manager.apply_style()`) and grabs any dialog in both themes in about a second — the Qt counterpart of the site's static harness, and for the same reason: a check that cannot finish in seconds is the wrong check.

### `src/compat.py` is the Qt/Anki gateway
Qt6-only (all Qt5 compat was removed in v3.0.0). **All Qt and Anki UI imports must go through `compat.py`**, not directly from `aqt`/`aqt.qt`. It re-exports widgets and defines Qt6 enum constants (e.g. `AlignCenter`, `DialogAccepted`, `MessageBox_Yes`) plus helpers (`StyledMessageBox` lives in `styled_messages.py`). When you need a new Qt symbol, add it to `compat.py`.

### Dual-context import pattern (important when editing `src/`)
Source modules are imported two ways: as a package inside Anki (relative imports) and by the test suite (which registers `src` as a package via `tests/conftest.py` and imports `from src.x import ...`). Many modules therefore use:
```python
try:
    from .compat import mw
except ImportError:
    from compat import mw
```
Preserve this pattern. `tests/conftest.py` fabricates the `aqt`/`anki` modules through a `sys.meta_path` import hook (not a fixture), so `src/` imports succeed without Anki.

### Configuration: `config.json` vs `meta.json` vs the collection config
- `config.json` (committed) — default settings only.
- `meta.json` (gitignored, auto-created by Anki in the add-on dir) — **the source of truth** for machine-local user settings + all connected remote decks. Managed entirely through `config_manager.py` (`get_meta()` / `save_meta()`). Never read/write these files directly elsewhere.
- **Anki's collection config** (`col.get_config` / `col.set_config`) — a **cache of the settings row each sheet was last parsed into**, under the single key `sheetcards::sheet_settings` holding `{sheet_id: entry}`. Anki's `config` table carries a `usn`, so anything stored there rides along to every machine the collection syncs to. Managed entirely through `src/sync_config.py`. It is a cache, never an editable store: the spreadsheet is the source of truth and a sync overwrites the entry.

### Sync data flow
`deck_manager.syncDecksWithSelection()` → `sync.syncDecks()` orchestrates everything. Per deck:
1. A Google Sheets **edit URL** is converted to a TSV export URL (`.../export?format=tsv`) — see `utils.convert_edit_url_to_tsv` / `get_spreadsheet_id_from_url`.
2. `data_processor.getRemoteDeck()` downloads + `parse_tsv_data()` + `build_remote_deck_from_tsv()` → a `RemoteDeck`. The header row is sorted into a `ColumnPlan` by `column_model.plan_columns()`, and the deck carries it as `RemoteDeck.plan`.
3. Still inside `build_remote_deck_from_tsv()`: if the row under the header is a settings row (`sheet_config.is_config_row`), it is parsed (`parse_config_row`) into a `SheetConfig` carried as `RemoteDeck.sheet_config`, and **removed from `rows` before anything is counted** — it must never reach `add_note()` or any metric. `first_row_offset` keeps logged row numbers matching the sheet.
4. `data_processor.create_or_update_notes()` creates/updates/deletes Anki notes. It caches the parsed settings (`cache_deck_sheet_config()` → `sync_config.cache_sheet_settings()`) and calls `templates_and_definitions.ensure_custom_models()`, which provisions the Basic/Cloze note types from `plan` (fields) + `sheet_config` (templates). Paths that provision a note type without the downloaded deck in hand read the cache back through `get_deck_sheet_config()`.

### Column model & note keying (`src/column_model.py`)
There is **no fixed column list**. The sheet decides the schema: only a handful of headers are reserved, and every other column becomes a note field named exactly like its header — so headers can be in any language. Row 1 is the header row; row 2 is either data or the optional **settings row** (see *Presentation* below).
- **Reserved headers** (matched case-insensitively, surrounding whitespace and BOM ignored — `column_model.normalize` / `clean`):
  - `ID` — the stable per-row key; never regenerate it. **Optional**: a sheet without it is keyed by its first content column (`column_model.derived_ids` — NFC, trimmed, whitespace collapsed; a repeat, case-insensitively, becomes `word (2)`, `word (3)`), so fixing a word's spelling makes a new note. On such a sheet the `#config` marker opens the first column's own cell (`#config name=X; size=40`); `sheet_config.marker_parts` splits off the sheet-wide keys (`_DECK_ONLY_KEYS`: `reverse`, `theme`, `name`, `next`, `shape`) and the rest, `align`/`speed` included, stays the column's.
  - `SYNC` — per-row gate (`row_is_marked_for_sync`, truthy values in `SYNC_TRUE_VALUES`). **A sheet with no SYNC column syncs every row** — absence means "no gating", not "nothing syncs".
  - `SUBDECK 1..N` — one level of the deck path each. Ordered **by the number, not by column position** (`subdeck_level`), and empty levels are skipped (`deck_path`).
  - `TAGS` — extra tags, comma- or semicolon-separated (`tags_of`).
- `plan_columns(headers)` sorts a header row into a `ColumnPlan` (`id_header`, `sync_header`, `tags_header`, `subdeck_headers`, `content_headers`, `duplicates`). A repeated header is honoured once — first occurrence wins. The `ColumnPlan` is threaded through parsing, note creation and note-type provisioning; most `data_processor` functions take it as `plan`.
- **Note types (models)** are `SheetCards - {deck} - Basic` and `- Cloze` (`utils.get_note_type_name`, `templates_and_definitions.create_model` / `ensure_custom_models`). Fields are `plan.note_type_fields()` = `["ID"] + content_headers` — `ID` leads because Anki uses the first field for duplicate detection. There is **no `- Reverse` note type**; the reverse direction is a second card *template* on the same note type (see below). `name_consistency_manager.py` keeps the names in sync when a deck is renamed.
- **Schema drift is asymmetric on purpose**: adding a column adds the field (`add_missing_fields`) and, unless the settings row says otherwise, puts it on the back of the card (`card_layout.split_sides`); **removing a column stops rendering it but never removes the field**, because dropping it would destroy content the user already collected.
- **Note keying**: notes are matched by the plain spreadsheet `ID` (or the derived one), read straight out of the note's `ID` field (`data_processor.get_existing_notes_by_id`). One row is always exactly one note. There are no `[MISSING_*]` sentinels and no `_REV` keys any more.
- **Cloze** is auto-detected per row by scanning **every content column** for `{{c1::...}}` (`data_processor.row_has_cloze` → `has_cloze_deletion`), which routes the row to the Cloze note type.
- Deck hierarchy: `tsv_model.deck_root_name` — a sheet with `name=` is filed **as typed**, any other as `sc_{deck}` (so unnamed decks already imported do not split; a named set imported before this sat under `sc_X`, and the add-on renames that deck to `X` in place through `local_root_name`/`name_consistency_manager`) — followed by the row's `SUBDECK` levels (`utils.get_subdeck_name`, `data_processor.determine_target_deck`) — a sheet with no `SUBDECK` columns keeps everything in the deck root. Tags (`data_processor.build_tags`): `sheetcards`, `sheetcards::<subdeck path>`, plus whatever `TAGS` lists.

### Presentation: the sheet's settings row (`src/sheet_config.py`, `src/card_layout.py`, `src/sync_config.py`)
**How a card looks is a property of the sheet, not of the deck.** The pipeline is parse → render → cache:
- **`src/sheet_config.py` parses it.** Row 2 is the settings row when its `ID` cell (or, with no `ID` column, its first cell) is `#config` or starts with `#config ` (`is_config_row`, matched lower-cased; anything directly after the marker must be a non-alphanumeric separator, so `#config;align=left` counts while a column value like `#configuration` does not). `parse_config_row(row, plan)` returns a `SheetConfig` (`fields: {header: FieldConfig}`, deck-wide `align`/`speed`/`reverse`, `present`, `warnings`). Cells are `key=value` pairs split on `;`; a bare key is a flag. Only `plan.content_headers` + the ID cell are read. Per-field keys: `side` (front/back/hide), `size` (int, `px` suffix tolerated — **6–200** as a font size, **1–2000** as a media width), `color` (`muted`/`accent` → `var(--sc-*)`, the real CSS named-colour list, or `#hex`), `align`, `tts`, `voices`, `speed` (**0.5–2.0**), `label`, `type` (bare or `type=nc`), `subdeck`, `font` (a key of `FONTS` or any family name), `math` (bare or `math=block`), `code` (bare or `code=python`), the flags `bold`/`italic`/`hint`/`furigana`/`cloze`/`draw`/`sort`/`rtl`/`vertical`, and the media kinds `image`/`audio`/`video` (`MEDIA_KINDS`). Deck-wide keys (`_DECK_KEYS`): `align`, `speed` (0.5–2.0), `reverse`, `theme`, the two identity keys `name` and `next` (see *Sheet identity* below), and `shape` (the note type's shape at the last download — kind, fields, card templates — written by Create sheet and hidden from the cell like `next=`; Sheet to Anki compares it to word the Merge note types notice).
- **Media columns say the cell holds a bare URL.** The three kinds share one `FieldConfig.media` attribute — a column holds one kind, and a second different one is ignored with a warning. Two checks deliberately run **after** the whole cell is parsed, at the bottom of `parse_config_row()` rather than in `_apply_field_pair()`: `size`'s range depends on whether the cell turned out to be media (so `size=480; video` == `video; size=480`), and `tts`/`furigana` are stripped from a media column with a warning because they would act on the address itself (speech would read the URL aloud).
- **Nothing is silently dropped.** An unknown key, a bad value or an out-of-range number appends to `SheetConfig.warnings` naming the column; the value is refused, never clamped. `data_processor.build_remote_deck_from_tsv()` echoes each warning to the debug log under the `SHEET_CONFIG` category, and the cache carries them to the dialog. **Each warning is a `SheetWarning`** — a `str` (the English sentence the add-on and log show) that also carries a `code` from `sheet_config.WARNING_CODES` and its `params`, raised through `_w(code, text, **params)`; the site gets `warning_codes()` from the analyzer and says it through `site/sheetwarnings.js` (`WARNINGS[code].en/.vi`, `warningText`, unknown code → the English text). A new warning needs a code, an entry in both languages and a sample in `tests/test_site_warnings.py`, which checks every code is raised, listed, translated, and that the site's English equals the parser's word for word. Parser errors (`pythonMessage`) map to i18n keys the same way.
- **`tts` requires a full language code** (`^[a-zA-Z]{2,3}[-_][a-zA-Z0-9]{2,4}$`, normalised by `normalize_tts_language` to `zh_CN` shape). Anki matches a TTS tag to an installed voice with an **exact** string compare (`aqt/tts.py`: `if avail.lang == tag.lang`), so a bare `zh` matches nothing and plays silence. Short codes are rejected rather than guessed at — guessing `zh_CN` for a Traditional-Chinese learner would be wrong *and* inaudible. `voices` is a preference (Anki falls back to any voice of that language), and a language with no installed voice is silent with no error.
- **Any card with a spoken column carries a collapsed `TTS voices` block on its answer** (`card_layout._tts_debug_block` + `_TTS_VOICES_SCRIPT`). Which voices exist is a property of the *reviewing device*, so it cannot be answered in a dialog: `aqt.tts.all_tts_voices()` reports the desktop's voices, never the phone's, and the phone is where a wrong-sounding voice is usually met. Anki's `{{tts-voices:}}` renders one tag per installed voice, **joined by `<br>`** — so the script scans the text with a global regex rather than splitting it into lines, or it would find only the first voice. **What a device prints is not what a sheet may write**, and an iPhone gets all three wrong at once: `{{tts en-US voices=Apple_Ava_(Premium):Front}}` — the code is hyphenated where `normalize_tts_language` forced an underscore (so the compare ignores case and separator, or a phone holding 28 `en_US` voices reports none), the entry is a *whole* tag with the field still on it (so everything after the `:` is cut, or the cell gets a voice no device has), and the Enhanced voices are listed a second time in a group of their own (so entries are deduped). Voices whose name says `(Premium)`/`(Enhanced)` sort first, because a robotic default is the reason the block was opened, and Apple's MacinTalk joke set (`_NOVELTY_VOICES` — Zarvox, Bells, Boing, Whisper…) is **not offered at all**: nineteen of an iPhone's twenty-eight `en_US` voices are jokes, nobody learns a language in the voice of a cello, and a list where Zarvox outnumbers Samantha is one nobody reads to the end — which is the only thing the block asks of a reader. Thirty voices come out as eleven. This is the one place the block knowingly shows less than the device reported; it shipped for a day behind a `+ 19 novelty voices` button and the button was the clutter the filter was for. A language whose *every* voice is a novelty keeps them, since dropping the lot would leave a heading with nothing under it. The names are matched whole against the spelled-out name, so `Google_Bells_of_Dublin` is a voice, not a joke. What survives that splits again, and **only a language's own voices are listed outright**: a name the device reports under *more than one language* is a character preset over one shared model — Eddy, Flo, Grandma, Grandpa, Reed, Rocko, Sandy, Shelley are under every major language an iPhone speaks, and nobody recorded Grandpa in Mandarin — so they sound like each other and bury Samantha and Ava under eight variations on a personality. They collapse to a `+ N shared voices` button that appends them where it stood. **This is derived from the device's own list, not from a list of names in this repo**: count the languages a name appears under and the answer falls out, on any platform, for whatever ships next — which is why the evidence has to come from `all` (every language the device reported) rather than from the filtered rows. `en_US` on the iPhone this was built against goes from thirty voices to three lines. The same two guards apply: a language whose every voice is shared keeps them all, and a device that speaks one language shares nothing. When nothing matches, **the codes the device reported are printed** rather than an instruction to go and check them — nothing else on the card can know how that device spells them; the ones sharing the language are shown alone when there are any. `tests/test_card_layout_voices.py` runs the script in node against a dump captured from a real iPhone, since none of this can be reached from Python.
- **Nothing a template emits may contain a doubled brace — a `<script>` and its comments included.** Anki scans the whole template for replacements, so an example tag written down in a JS comment is a reference to a field that does not exist, and the note type is refused outright with `Field 'Front' not found` — the deck stops syncing and nothing says which template did it. It shipped exactly that way once, in a comment explaining the shape of the voice list; the regex in `_TTS_VOICES_SCRIPT` escapes every brace for the same reason. `TestNothingInAScriptLooksLikeAField` in `tests/test_card_layout.py` scans every `*_SCRIPT` constant for the character pair **and** asks a real Anki to save the note type — the suite's mock stores any string at all, so only Anki can tell a valid template from one that will be refused on the machine of whoever synced. That harness reaches the pure modules through a fabricated `sc` package over `src/`, the way `tests/test_apkg.py` does: importing `src.*` pulls in `src/__init__.py` → `compat` → `aqt` → Qt, and a headless CI runner has no `libEGL`.
- **A generated template carries no commentary of its own.** Every `*_SCRIPT` is built as a Python string concatenation with the reasons written as `#` comments *outside* the string — that is why `_DRAW_SCRIPT` and `_CODE_SCRIPT` look the way they do, and `_TTS_VOICES_SCRIPT` was rewritten to match after shipping as a triple-quoted blob full of `//`. A template is generated, overwritten on every sync, and read only by someone already lost; an explanation inside it is copied into every note type on every synced device and helps nobody. `test_no_script_carries_its_reasoning_onto_the_card` fails on a line that starts with `//` or `/*` (a bare `//` is the middle of a CDN address). It keeps the languages the sheet declared, groups by language and rewrites each entry as the sheet's own `voices=` syntax, because the reader is about to edit a spreadsheet cell, not a template. Each row plays the card's real content through the Web Speech API — which **QtWebEngine does not implement**, so the play buttons are left out on the desktop rather than shipped inert. An empty list distinguishes the two failures: no voices at all, or voices for other languages only (a wrong `tts=` code). There is no opt-in flag — whoever wrote `tts=` and heard a robot is the least likely to know one exists, and collapsed it costs one line.
- **`src/card_layout.py` renders from it.** `split_sides(plan, sheet_config)` applies the default (first content column front, rest back), `side=` overrides, `side=hide` drops; an empty front promotes the first visible back field. `build_templates(plan, sheet_config, is_cloze)` returns the `{"name", "qfmt", "afmt"}` list. Per field: `_inline_style` (size/color/bold/italic/align), `_reference` (plain, `{{hint:…}}` or `{{furigana:…}}`), `_tts_tag` (`{{tts LANG voices=… speed=…:Field}}`, field-level `speed` beating the deck-wide one — and **`kana:` chained in for a `furigana` column**, because Anki gives the voice the field's text and the text of a furigana cell is `日本語[にほんご]`, so the plain tag says the word, the bracket, then the word again; `kana:` not `kanji:`, since the sheet wrote the reading down precisely so nothing would have to guess it, and a bracket-free cell passes through either filter unchanged). Both the field div and the TTS tag are wrapped in `{{#Field}}…{{/Field}}` so an empty cell renders — and speaks — nothing.
- **A media field takes a separate branch**: `_rows` skips `_inline_style`/`_reference` and calls `_media_html`, formatting `_MEDIA_ELEMENTS[cfg.media]` around `{{Field}}` (`size` → `max-width`; the `<audio>` element has no `{style}` slot, so `size` is refused there with a warning). `color`/`bold`/`italic`/per-column `align` are inert on a media column and **say so** in `SheetConfig.warnings`; `hint` wraps the element in a `<details class="sc-reveal">` disclosure, because Anki's `{{hint:}}` reveals the field's *text*, which on a media column is the URL. The `src` is a **remote URL** — nothing lands in `collection.media`, so these cards need the network. `src/ui/card_layout_dialog.py` keeps its own hand-copied `_FIELD_KEYS` tuple (it does include `media`); `test_dialog_field_keys_match_fieldconfig` pins it to `FieldConfig`, so update both together.
- **`video` is a framed player, not `<video>`** — `_MEDIA_ELEMENTS["video"]` emits `<iframe class="sc-embed">` (16 : 9 from the stylesheet, since an iframe has no intrinsic size). That is the only thing that can play what people actually paste. The address is rewritten by **`tsv_model.normalize_embed_url`**, called from `build_remote_deck_from_tsv` **before `add_note`** — never at render time, because a template can substitute a field but cannot transform one, and YouTube refuses to be framed outside `/embed`. Doing it before `add_note` also means the sync's change comparison (`data_processor`, `note[header] = note_data.get(header)`) sees the stored value, so a row does not read as modified on every sync. The rewrite is idempotent; an unrecognised address passes through (a direct `.mp4` plays in the frame); a channel/playlist/folder passes through **with a warning** appended to `sheet_config.warnings`. Framed players are blocked on AnkiDroid/AnkiMobile.
- **The deck path has two sources, and the settings row wins.** `SUBDECK n` headers are reserved (never fields); `subdeck=n` in a column's settings cell makes an **ordinary content column** a level of the path. **It is never drawn on the card, and every card key in its cell is refused by name** — `card_layout._is_drawn`, `sheet_config._CARD_KEYS` — because where a note is filed is a bigger thing than how one card looks, and one rule (a deck level is a deck level) beats two. It shipped drawing the column, then shipped drawing it only with an explicit `side=`; both were the same mistake at different sizes. `column_model.deck_path(row, plan, sheet_config=None)` prefers `sheet_config.subdeck_columns` and falls back to `plan.subdeck_headers`; the config is threaded through `build_tags`, `determine_target_deck`, `apkg.build_package` and the site's `ANALYZER`. **`sheet_config.resolve_roles()` is the single place that derives `cloze_field`, `type_field` and `subdeck_columns`** from the per-column settings — called by `parse_config_row` (with a `warn`) and by `sync_config.from_dict` (without one, since the warnings were recorded at parse time). Before it existed, a note type rebuilt from the cache came back with no `cloze_field` and Anki refused to save the template.
- **Three per-column keys are about the note or the reader, not the card's look.** **`sort`** names the column Anki lists notes under in the browser and sorts a deck by — stored as an index into the field list by `templates_and_definitions.apply_sort_field`, called from `create_model` and after `add_missing_fields` in `ensure_custom_models`, and idempotent so an unchanged sheet does not rewrite the note type every sync. The default is field 0, which is `ID`, so without it a deck lists as `w01, w02, w03`. Resolved in `resolve_roles` beside `cloze_field`/`type_field`; refused on a media column; **allowed on a `subdeck` column**, unlike every card key, because filing a note and listing it are both properties of the note. **`rtl`**/**`vertical`** are the two writing directions (`direction: rtl` right-aligns unless `align` says otherwise; `writing-mode: vertical-rl` keeps Latin upright with `text-orientation: mixed`) — one direction per column, `rtl` wins. **`font`** exists for Han unification: `直`/`骨` are one code point drawn differently in Chinese and Japanese, and `sc`/`tc`/`jp`/`kr` import a Noto face via `_font_imports()`, which must stay at the **top** of the stylesheet because `@import` is only legal there.
- **`math` needs no library and `code` needs one.** Anki ships MathJax, so `math` is only delimiters — `\(…\)`, or `\[…\]` for `math=block`. `code` emits `<pre class="sc-code"><code class="language-…">{{text:F}}</code></pre>` (`text:` because a pasted cell arrives with markup in it) and `_one_template` appends `_CODE_SCRIPT` to whichever side has one, loading `HIGHLIGHT_JS` the same idempotent way `draw` loads HanziWriter. **No highlight theme is imported** — the token colours live in `_css` for both light and `night_mode`, because a ready-made theme paints its own light background and sits on a dark card as a white rectangle. The preview page runs the card's scripts, so `code` colours itself there; MathJax is *not* in a browser, so `site/cardframe.js` adds it to the card document when the rendered HTML contains a delimiter.
- **A row that names no level lands in `column_model.UNSORTED_DECK` (`Unsorted`), and there is no directive for it.** Applied in **`deck_path`** as the single level of an otherwise empty path, so the deck and the mirrored tag follow from one place. It fires **only on a sheet that has levels** (a `SUBDECK n` header or a `subdeck=n` column) — with nothing to be unsorted from, a two-column sheet must not find every note wrapped in a folder; a partly-filled path is left alone. v6.21.0 shipped this as `#config unsorted=<name>` and v6.22.0 took the key out again: a sheet that sorts is already saying a row belongs somewhere, so the row that names none has an answer either way, and the key could only ever have been a way to leave those rows loose among the folders. Do not reintroduce it.
- **`side=hide` + `tts` is heard without being read.** `card_layout.spoken_sides` returns the not-drawn columns that still declare `tts`, and `build_templates` renders their tags once and hands them to `_one_template` as a `(front, back)` pair — rendered rather than as names, because the reverse card gets the same pair the other way round. `_side_of` maps `hide` to the *default* side rather than returning it, so a column that is not drawn still belongs somewhere, which is what decides where its voice goes.
- **`draw` is a writing box, and the only thing in a card that is not HTML.** A flag in `_FLAGS` → `FieldConfig.draw`. `card_layout._draw_html` emits `<div class="sc-draw" data-sc-char="{{text:F}}" data-sc-size=… data-sc-quiz=…>` and `_one_template` appends `_DRAW_SCRIPT` to any **side** that has one; the script loads `HANZI_WRITER` (a pinned CDN URL) into `document.head` once and is idempotent, because Anki re-executes a card's scripts every time it draws the card. **Which job the box does is decided by the side, not by a directive** — `_rows(..., quiz=True)` from the question, default `False` from the answer — so there is nothing to keep in step. `size` is the side of the square (media's 1–2000 range, not the 6–200 font range) and is kept off the wrapper's `font-size` via `_inline_style(with_size=False)`; `color` deliberately still applies, because the strokes are drawn in the colour the box inherits. `draw` is refused on a media or cloze column, and `bold`/`italic`/`furigana` warn as inert. The `:empty::before` rule in `_css` is what a card shows with no network. **The preview runs the script like any other card script** — `cardFrame`'s sandbox is `allow-scripts allow-same-origin` and nothing filters a template's `<script>`, so HanziWriter loads from the CDN inside the frame and the box on the question is a real quiz square, blank because that is what quiz mode draws until you make a stroke.
- **Cloze is a sheet-level choice, not a per-row one.** A column declares `cloze`; `parse_config_row` resolves it to `SheetConfig.cloze_field` (one per sheet, extras warned), `split_sides` forces it onto the front, and `_reference` applies `{{cloze:}}` to **that column only**. Routing uses `bool(sheet_config.cloze_field)` in `data_processor.create_new_note`/`update_existing_note` — **not** `row_has_cloze`, which now only feeds the "row has markup but no column declared" warning in `build_remote_deck_from_tsv`. Wrapping any other column would blank it: Anki renders a clozed field holding no deletion as *nothing*. The cloze **back repeats the prompt through `{{cloze:Field}}` instead of `{{FrontSide}}`**, because the filter has to appear on both sides. Extra templates on a cloze note type generate no cards, so `reverse` is skipped for them.
- **`type`** → `SheetConfig.type_field`, one per sheet (Anki honours one `{{type:…}}` per card). `_type_box` emits `{{type:F}}`, `{{type:nc:F}}` (diacritic-insensitive) or `{{type:cloze:F}}` when the column is also the cloze column, on the **question** only, and never on the reverse template.
- **`src/sync_config.py` caches the result** (`to_dict`/`from_dict`, `cache_sheet_settings`, `cached_plan_and_config`, `forget_sheet_settings`) under `sheetcards::sheet_settings`, so `update_existing_note_type_templates()` can rebuild templates outside a sync and the dialog can show a deck's settings without downloading the sheet. A cache entry with no `content_headers` yields `(None, None)` — rendering from it would blank the card.
- **`src/apkg.py` packs a sheet into an `.apkg` (legacy schema 11) for the preview site's download button — the add-on itself never calls it, since inside Anki it writes to the collection directly. It consumes `note_type_fields()`/`build_templates()`/`get_subdeck_name()`/`build_tags()`, so only the packaging is new; note guids derive from the sheet's identity and the row `ID` so a re-import updates, and `mod` comes from the clock because Anki only overwrites a *newer* note. A repeated `ID` keeps its first row (the database would refuse the second). `tests/test_apkg.py` runs a real Anki in a subprocess — the suite's mock cannot tell a valid package from a broken one.

### `src/ui/card_layout_dialog.py` is a read-only viewer** (`Ctrl+Shift+C`): the parsed sides, the per-column settings, the warnings, the TTS voices installed on this machine, and a preview. **Do not add editing controls to it.** Two places able to change one setting means the loser is silently overwritten on the next sync, which is exactly how a control ends up doing nothing with no way to tell. Settings are changed in the sheet and re-synced.

One sans-serif family and one type scale for everything the page says; monospace only for strings that came out of a spreadsheet.

The card's own document is listened to (`wireFrame`, possible because the frame is same-origin): **a tap anywhere that is not a control turns it** (`INTERACTIVE` lists what is a control — TTS buttons, type-in boxes, draw boxes, hints, players), **a sideways drag follows the finger and throws the card** to the next one, ←/→ and Space work in or out of the frame, and Enter in a type-in box asks for the answer with the typed text carried across to the answer side. Row fate (`skipped`/`invalid`), stranded cloze, missing fields and unknown filters are notes under the card; tags under those.

**There is no deck-name field in Sheet to Anki.** The name comes from the sheet (`name=`) or, without one, from the file; `chooseDeckName()` takes what the source said.

**Sheet identity (`name=`, `next=`; `apkg.resolve_identity`, `site/identity.js`).** A package's guids, deck ids and note type id derive from one identity, in this order: (1) the marker's `name=` — `#config name=Từ vựng tiếng Anh` is both the deck name shown and the identity, normalised by `apkg.deck_identity` (NFC, whitespace collapsed, case-folded) into `name:<…>`; (2) the Google spreadsheet id + tab; (3) the file name via `identity.fileIdentity` — extension and a ` (n)`/`(n)`/`-n` download suffix stripped (a bare ` n` is *kept*: `HSK 1`/`HSK 2` are two decks), keyed as `file:<stem>.tsv#<tab>` so the old Create sheet hand-off keeps its id. A named sheet's note type id is `(identity, Basic|Cloze)` only; **an unnamed sheet keeps the exact legacy formulas** (model id includes the deck name), pinned by `tests/test_apkg.py::TestLegacyIdentity` — never change them, or every deck already imported duplicates. Consequences, all deliberate: two sheets with one `name=` are one deck; renaming is a new deck. Create sheet therefore asks for the name in the template step (`#tpl-name`, required, warned when `identity.nameUsed`), asks before a rename, never adds `name=` to a sheet opened without one (it *offers*, `#nameoffer`, since that changes the identity once), and kept/built-in templates carry no `name=`/`next=`. `next=` is the ID high-water mark (`sheet.next`, written by `exportGrid`, kept out of the visible cell): `nextId()` never issues at or below it, so a deleted word's ID is never reused; IDs written twice or left empty block every way out (`idsBlock`).

**The add-on keys notes the same way, so a phone's .apkg and a desktop sync are one set of notes** (`tests/real_anki_overlap.py`, real Anki, default import options, both orders). `templates_and_definitions.sheet_identity` = `resolve_identity(get_deck_id(url), remote name, sheet_config)` — `get_deck_id` (`{spreadsheet id}#{sheet}`) already equals the site's Google key. From it: (a) `create_new_note` stamps `apkg.note_guid`; (b) a new note type is added under `apkg.model_id` (`_add_with_id`, Anki's legacy add-or-update with `preserve_usn_and_mtime`, usn −1 — the public add refuses a preset id; falls back to a random id), and an existing one with that id (from an .apkg) is reused; (c) `restamp_guids` moves older random-guid notes onto the derived guid once (idempotent, skips a guid another note holds); (d) `adopt_imported_notes` finds rows by guid outside the deck — on our note type they join the sync, on another one they are left alone and the row is skipped with a summary warning, never retyped (that would reset history). **Naming follows the site, not the reverse**: changing the site's one-sheet `base` to `base::tab` would move every unnamed deck already imported onto a new note type id (legacy model id includes the deck name). So a sheet connected as its file's only sheet gets `#sheet=X&only=1` (`utils.url_for_sheet(only=)`, `sheet_is_only`) and is named `{file}` (`DeckNameManager.sheet_remote_name`); a URL stored earlier keeps `{file}::{sheet}`. `name=` wins in the add-on too (`deck_manager.remember_declared_name` from each download, `declared_name_for` before the title, persisted as `declared_name` in meta.json) and is used **as written** — `generate_local_name` skips `clean_name` for it, as `apkg.declared_name` does. `other_decks_models` keeps a deck from counting the notes of a sheet connected later inside it (`sc_{file}::{sheet2}` under `sc_{file}`). Limits: an unnamed sheet matches only while the add-on's title equals the site's file name; an add-on deck made before this keeps its random note type id, so its later .apkg imports report *conflicting* (no duplicates) — `name=` plus Change Note Type is the way out.

**A changed note type needs Merge note types, once.** With Anki's default import options (merge off, update notes/note types *if newer*) any change to the field list or card templates makes every note `conflicting` — verified in real Anki 25.07 by `test_default_import_options`. Sheet to Anki remembers each identity's last package shape in `localStorage["sc-deck-shapes"]`, builds the next package with the old fields kept in front (`apkg.kept_fields`, so a removed or moved column is *not* a schema change and one merge is enough), and on a change shows `#schemanote` before and `#done-schema` after the download: turn on **Merge note types** and set **Update notes** to **Always** (merging re-stamps the existing notes, so *if newer* would then skip them). **A template taken out (`reverse` off) needs no merge**: the package keeps it by name as a stub that renders nothing (`apkg.kept_templates`/`stub_template`, `{{^ID}}…`, no card rows), so the import updates and Anki lists the old reverse cards under **Tools → Empty Cards** — which the page says once (`identity.droppedTemplates`, `shape.stubs`, `#schemanote`/`#done-schema`); merging instead would keep the real template and Empty Cards would find nothing (both verified in real Anki). Basic ↔ Cloze cannot be merged at all; the notice says to Change Note Type in Anki instead.

**Two pages, one set of parts.** `site/sheet.html` (Create sheet) and `site/create.html` (Sheet to Anki) both draw a deck and a card, so both import **`site/decktree.js`** (`deckTree` builds the hierarchy from `{deck, kind}` rows, `treeHtml` renders it — `pick: true` makes each level a `data-deck` button for the preview's filtering, off makes them spans) and **`site/cardframe.js`** (`cardDoc` builds the card's own document — stylesheet, `card`/`night_mode` body classes, the tts script, the optional `data-sc-col` ring — and `cardFrame` wraps it in the sandboxed iframe). The card document used to exist twice, and the copy in the old editor had already lost the `<meta name="referrer">` that keeps YouTube from refusing to be framed. Neither page can be exercised without Pyodide, so **`tests/test_site_components.py` imports both modules in node** and checks their markup; that is the only guard on a change that would break both pages at once. On a wide screen Create sheet is a grid of areas — the sheet, the column panel and the deck tree on the left, the card held sticky on the right (`.lookside`) clear of the sticky `.outbar`.

**Create sheet's grid behaves like a spreadsheet, and no grid library is involved.** What makes it possible is one rule: `.sheet .cell input/textarea { pointer-events: none }` except in `.cell.editing`, so a drag lands on the cells and can be read as a range. On top of that: `ui.sel` (anchor + far corner; row 0 the names, row 1 the settings row, row 2+ the words; column −1 is column A, the IDs), `paintSelection` writing `sel`/`anchor`/`edge-*` classes (the border is drawn around the *range*, so each cell is told which of its sides is an edge), `copy`/`cut`/`paste` handlers moving TSV, a fill handle repeating a block across what it is dragged over, a right-click menu (insert / move / delete rows, insert / delete columns, clear), **a pasted block growing the sheet** (onto a selection it adds rows and columns as far as it reaches; with nothing selected a whole sheet — `ID` header or `#config` — replaces this one and plain rows are appended, taking the first cell as the ID only when every one looks like an ID and there is one cell more than columns), and an undo stack of whole-sheet snapshots where **a step is one action, not one keystroke** (`markRun(tag)` coalesces a run of typing in one cell; `mark()` ends it). Touch deliberately keeps the old behaviour — a tap types, because the drag gesture already scrolls the grid. A grid library (jspreadsheet-ce, RevoGrid, Tabulator) was considered and refused: 200–400KB vendored past a CSP that blocks CDNs, for a sheet of flashcards, in exchange for control of the cells the directive chips have to point at.

`site/anki.js` is the sole exception and the only approximation on the page: `{{Field}}`, `{{#Field}}`, `{{cloze:}}`, `{{hint:}}`, `{{furigana:}}` and `{{tts}}` are interpreted by **Anki itself** (Rust), so there is nothing in this repo to reuse. Its cloze filter deliberately returns `""` for a field with no deletion because that is what Anki does — verified against a real `anki.collection.Collection`.

**`{{type:…}}` is not a filter, and treating it as one printed the answer on the question.** Anki's renderer leaves the tag alone; the *reviewer* swaps it for an `<input>` and, once the answer is shown, for a character diff — so `anki.js` intercepts it before the filter chain (`typeBox`) and emits an input plus an empty result div carrying `data-typeans` (the expected text, and whether `nc` is on; `cloze` resolves to that card's deletions joined by `", "`). **`site/typeans.js` draws the comparison**, reproducing `Collection.compare_answer` down to the markup — `typeGood`/`typeBad`/`typeMissed` spans, a `-` standing in for each character left out, a substitution drawn with no dash, and the *expected* spelling shown back on a match so `nc` teaches the accent. `compareAnswer` is written self-contained because `typeansRuntime()` serialises it with `toString()` into the card's own document (no module loader in there); `tests/test_site_typeans.py` pins it to output captured from a real Anki 26.08, and `cardframe.js` carries the three colours, which come from **aqt's `reviewer.css`, not from any note type**. `cardDoc` marks the body `data-answered` on every tab but `front`, which is what reveals the comparison before anything is typed. Deploy is `.github/workflows/pages.yml`, triggered by changes to `site/**`, `src/**` or the build script.

**Known cloze defect the preview surfaces**: a row is routed to the Cloze note type when *any* content column holds `{{c1::…}}`, but `card_layout` only applies `cloze:` to the **front** fields. Anki renders a clozed field with no deletion as nothing, so such a row yields a blank prompt with the raw markup on the answer. Fixing it properly means changing how note types are provisioned (the template must know which column carries the deletion); the docs' *Card types* page (`docs/site/card-types.md`) documents declaring the column with `cloze`.

### What this add-on deliberately does not do

Two features were built and then removed in full, and the reasons are the same reason: **the spreadsheet is the source of truth, and a feature that forgets that is a feature doing someone else's job.**

- **No backup or restore.** Anki already backs the whole collection up (Preferences → Backups) and does it before risky operations. Everything this add-on creates comes back from a sync, so a deck is never the thing at risk; the only irreplaceable state is `meta.json`, a few KB naming the connected links. ~1,750 lines went — a retention limit, safety copies, an `.apkg` export path and a pre-sync backup step in `syncDecks()`. If the link list ever needs saving, that is an export button writing one JSON file, not a subsystem.
- **No image processing.** It solved "a picture pasted into a cell is not something Anki can reach", and charged an ImgBB account, an API key, a deployed Google Apps Script web app and an `Access: Anyone` deployment for it. A media column (`image` in the settings row, a URL in the cell) solves the same problem with none of that. ~960 lines went, along with `HTML IMAGE` as a reserved concept.

- **No choice of deck-options mode.** Every connected deck studies under one preset, `SheetCards - Default Options`. There were three modes — shared, individual, manual — in a window with a shortcut of its own, which is a setting about a setting: a study preset is Anki's to configure and two clicks away in its own deck options, and offering one per deck was offering to fill someone's preset list with copies of the same numbers.
- **Three settings windows became one.** `Ctrl+Shift+O` opens `settings_dialog.py`: the AnkiWeb hand-off and debug logging, saved on Save rather than on each toggle (the debug window wrote on every tick, so its Cancel did nothing). The in-app log viewer went with it — it was a text editor with everything taken out, and the window shows the path and opens the folder instead.
- **The Card Layout window no longer lists installed voices.** `aqt.tts.all_tts_voices()` reports the *desktop's* voices, and a wrong-sounding voice is met on a phone; every card with a spoken column carries the list itself now (`card_layout._tts_debug_block`).

All of this was removed while the add-on had no users. Do not reintroduce any of it: the second way to do a thing is the one that gets out of date.

### `IS_DEVELOPMENT_MODE` (build-time flip)
Defined `True` in `templates_and_definitions.py`. The AnkiWeb/standalone build scripts **rewrite it to `False`** in the packaged copy. It gates the "Import Test Deck" menu item and `TEST_SHEETS_URLS`. Leave it `True` in the repo.

### The example workbook (`examples/`)

The single source of examples for everything: `README.md`, `docs/site/examples.md`, `docs/ANKIWEB_DESCRIPTION.md`, `TEST_SHEETS_URLS` (the dev-only *Import Test Deck*), the preview's opening sheet and the landing page's demo cards all point at **one** address —
`https://github.com/tannc28/sheetcards/blob/main/examples/sheetcards-examples.xlsx`.
It used to be a Google Sheet nobody here could edit, which is how it came to describe a schema the add-on had outgrown.

- **The grids live in `SHEETS` at the top of `scripts/build_examples.py`; the `.xlsx` is generated and committed.** Declaration order is tab order and the key is the sheet name. The script writes the workbook with a stdlib ZIP/XML writer (inline strings, no shared-string table) and reads the result back through `src/workbook.py` before writing it; `--check` fails instead of writing. Entries carry a fixed timestamp so an unchanged `SHEETS` rebuilds byte-identically. `examples/` holds exactly two files — the workbook and its README — and a test pins that.
- **Thirty-one sheets, ordered basic → advanced**, each a deck that also demonstrates one thing. **No sheet is the end of the tour** — one called `Finished deck` was renamed for saying the other fourteen were drafts. `site/app.js` opens its `DEMO_TAB` on `15 Theme + subdeck (màu, tầng)` rather than the first sheet, because a preview showing two columns and no settings row answers none of the questions people arrive with. There was an `Everything` sheet turning on every directive at once and an `Edge cases` sheet wrong on purpose; both are gone — fourteen columns of directives taught nobody how to write a settings row, and the warnings are covered by `tests/test_sheet_config.py` without a deck being broken for them. A new directive goes on the sheet whose deck would have wanted it. **A tab's name carries a Vietnamese gloss in brackets** (`06 Cloze (điền chỗ trống)`) — the workbook is demonstrated to Vietnamese learners and *cloze* is not a word they arrive with. Excel caps a sheet name at **31 characters** and `build_bytes()` refuses a longer one. **Media addresses are checked before they are written down**, not guessed: every picture and recording in the workbook was fetched once, and a Commons file is linked through `Special:FilePath/<name>` so the path hash cannot go stale.
- **`tests/test_examples.py` is the guard.** It fails if the `.xlsx` does not match the TSVs, if any sheet warns, if a sheet renders an empty front, if the three copies of the published URL disagree — and, most importantly, **if a settings-row key has no example anywhere in the workbook**. Adding a directive to `sheet_config.py` means adding it to a sheet in the same commit.
- The workbook is *not* shipped in the `.ankiaddon`: the packaging scripts copy an explicit allowlist (`__init__.py`, `manifest.json`, `config.json`, `README.md`, `LICENSE`, `src/`).

## Building & packaging

`scripts/create_ankiweb_package.py` and `create_standalone_package.py` produce `build/*.ankiaddon` ZIPs. AnkiWeb requires: files at the **ZIP root** (no parent folder), a valid `manifest.json`, and **no `__pycache__`/`.pyc`** — the scripts enforce and verify all three. The AnkiWeb variant strips the manifest to mandatory fields; the standalone keeps the full manifest. `validate_packages.py` checks an existing `.ankiaddon`.

## Gotchas
- **The add-on stays on `0.x.y` until it is declared official (`1.0.0`).** Numbering restarted at `0.1.0` in October 2026 and every earlier release and tag (up to v7.0.0) was deleted; the old changelog is in git history only. Bump the minor for a change in how a sheet is read, the patch for a fix.
- **The version lives in `manifest.json` and `pyproject.toml` and the two must always agree.** Do not write the current number into prose (that is exactly how this line went stale); read it from the files. **Releasing is driven by the version**: merging to `main` with both files bumped makes `.github/workflows/release.yml` tag, build and publish; merging without a bump finds the tag already present and stops. The run fails if the two files disagree, or if `docs/CHANGELOG.md` has no section for that version — so a release always carries notes.
- Requires Anki **25.x+** / Qt6 / Python 3.13 — do not reintroduce version-detection or Qt5 fallbacks.
